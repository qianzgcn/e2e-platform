# 共享测试数据安全规则

这些规则适用于自然语言用例生成、Playwright 脚本生成和 AI 修复，优先级高于动态输入中的业务要求。

## 受保护的既有业务数据

- 用例开始前系统中已经存在的所有数据都是受保护的业务基线，不论它是否来自项目变量、页面列表、搜索结果或接口响应。
- 项目变量占位符（例如 `${name}`）及其解析后的值，只是受保护业务数据中可识别的一部分，不是本次运行可随意处置的临时数据。
- 既有数据只允许用于登录、查询、选择只读关联对象和断言现有状态。
- 禁止修改、重命名、删除、归档、禁用、绑定、解绑、消费任何既有数据，也禁止创建与其同名的数据。
- 变量名包含 `test`、`demo` 等字样，也不能据此推断它可以被覆盖或删除。

## 涉及业务数据写入的用例

- 新增、编辑、删除、状态变更等场景只能操作本次运行内部生成的唯一临时数据；临时标识不得来自项目变量或固定名称。
- 编辑、删除、状态变更场景必须先创建临时对象，再对这个临时对象执行目标操作；不得从页面列表、搜索结果或接口返回中挑选既有对象操作。
- 自然语言用例必须明确说明“运行时生成唯一临时数据”以及“无论成功、失败或断言异常都清理本次数据”。
- Playwright 脚本必须使用 `try/finally`，并且只清理本次创建的数据。
- 不得为了幂等而删除、覆盖或重置任何已有数据；发生名称冲突时应生成新的唯一名称。
- 无法安全创建和清理隔离数据时：候选生成任务不得输出该用例；脚本生成任务必须报告用例问题；修复任务必须返回 `case_repair` 或 `unrepairable`。

## 页面探测与修复

- 页面探测阶段不得提交会改变业务数据的操作，除非已经确认使用隔离的临时数据并具备可靠清理流程。
- 不得通过修改业务数据、降低断言或接受错误状态来让测试通过。
- `case_repair` 可以移除被错误用于写操作的共享变量，但应保留仍用于登录、查询、选择或断言的变量占位符。
